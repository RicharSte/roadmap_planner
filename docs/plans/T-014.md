# T-014: macOS build `.app`/`.dmg`, README «Как установить», полный ручной прогон `docs/mvp-done.md`

Статус: approved

## Проблема

MVP функционально готово (T-001…T-013), но никогда не собиралось и не проверялось как конечный продукт:
нет `.app`/`.dmg`, в README нет инструкции по установке, а чек-лист `docs/mvp-done.md` отмечался только
по проверкам в `pnpm tauri dev`. Раздел «Сборка и передача» не пройден, два пункта «Сценариев
пользователя» не отмечены. Без этого нельзя закрыть MVP.

## Решения из интервью

- **Название приложения:** `productName` = «Roadmap» (сейчас шаблонное `tauri-app`). `identifier`
  (`dev.roadmap.app`) не меняем — ответ по умолчанию из Q10 (`docs/open-questions.md`). Меняем только
  `src-tauri/tauri.conf.json` (`productName`, `app.windows[0].title`) и описание/автора в
  `src-tauri/Cargo.toml` (были шаблонные `"A Tauri App"` / `"you"`). Имя Cargo-пакета (`tauri_app_lib`)
  и `name` в `package.json` не трогаем — внутренние идентификаторы, пользователю не видны, лишний риск
  регрессии ради MVP не нужен. В `docs/guide.md` добавляем заметку, где менять название, если
  понадобится позже.
- **Второй Mac для проверки `.dmg`:** недоступен. Пункт mvp-done.md «устанавливается и запускается на
  другом Mac» заменяем на proxy-проверку на этом же Mac: смонтировать `.dmg`, скопировать `.app` в
  `/Applications` (не запускать из `target/release` — это другой сценарий), ПКМ → «Открыть». Формулировка
  пункта в `docs/mvp-done.md` уточняется этой оговоркой.
- **Кто проходит ручной чек-лист:** пользователь — у агента нет доступа к GUI. Агент собирает `.app`,
  даёт точный построчный список шагов из `docs/mvp-done.md`, пользователь выполняет их в собранном
  приложении (не в `pnpm tauri dev`) и подтверждает построчно. Агент отмечает `[x]` только по
  подтверждённым пунктам.
- **Раздел README:** инструкция «собрать из исходников» — публичных релизов и CI пока нет (T-108
  в 1.1, не сделано), так что раздел описывает актуальный способ получить приложение.

## Решение

Переименовываем приложение в конфиге Tauri, собираем `pnpm tauri build`, проверяем результат через
proxy-установку на одном Mac, документируем сборку в README, и вместе с пользователем построчно
проходим весь `docs/mvp-done.md` в собранном `.app` (а не в dev-режиме) — финальная сверка перед
закрытием MVP может вскрыть то, что dev-режим скрывает (диалоги файлов, иконка, путь к бинарнику).
Отклонённая альтернатива: тащить подпись/нотаризацию в эту задачу — явно пост-MVP (`later.md` T-301),
не делаем.

## Критерии приёмки

- [ ] `pnpm tauri build` на macOS завершается без ошибок, создаёт `.app` и `.dmg`
      в `src-tauri/target/release/bundle/`
- [ ] Ручная проверка: `.dmg` смонтирован → `.app` скопирован в `/Applications` → ПКМ → «Открыть» →
      приложение запускается с проверкой Gatekeeper, не из `target/release`
- [ ] `README.md` содержит раздел «Как установить и запустить» (3–6 шагов, сборка из исходников)
- [ ] `docs/guide.md` содержит заметку, где менять `productName`/`identifier`
- [ ] `pnpm typecheck && pnpm lint && pnpm test` проходят после правок конфига (логика кода не менялась)
- [ ] `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test` проходят в
      `src-tauri/`
- [ ] Ручная проверка: пользователь построчно проходит каждый пункт разделов «Сборка и передача»
      (кроме Windows/T-015) и «Сценарии пользователя» `docs/mvp-done.md` в собранном `.app`,
      подтверждает каждый агенту → все подтверждённые пункты отмечены `[x]`

- `docs/backlog.md` — изменить — статус T-014

## Шаги

1. В `tauri.conf.json` и `Cargo.toml` поменять название/описание на «Roadmap» (см. «Решения из интервью»).
2. Собрать: `pnpm tauri build`. Если каталог `target` содержит старую сборку со старым именем — собрать
   с нуля (`cargo clean` в `src-tauri/`, если старое имя всплывает в артефактах).
3. Proxy-проверка `.dmg`: смонтировать, скопировать `.app` в `/Applications`, ПКМ → «Открыть», убедиться
   что окно открывается и не ругается Gatekeeper дальше первого предупреждения.
4. Дописать README: раздел «Как установить и запустить» (сборка из исходников, 3–6 шагов).
5. Дописать `docs/guide.md`: где менять `productName`/`identifier`, если понадобится позже.
6. Дать пользователю точный построчный список шагов из `docs/mvp-done.md` (кроме Windows) для прогона
   в собранном `.app`; получить подтверждение по каждому пункту.
7. Отметить подтверждённые пункты `[x]` в `docs/mvp-done.md`, уточнить формулировку пункта про
   «другой Mac» (прим. про proxy-проверку).
8. Обновить статус T-014 в `docs/backlog.md`.

## Тесты

Код логики не меняется — новых unit/интеграционных тестов нет. Проверяются только существующие
наборы (`pnpm test`, `cargo test`) на то, что правки конфига их не ломают, плюс ручной прогон как
единственный способ проверить сборку и UX инсталляции.

## Вне рамок

- Подпись и нотаризация macOS (`later.md` T-301, пост-MVP).
- Переименование Cargo-пакета (`tauri_app_lib`) и `name` в `package.json`.
- Windows-сборка (T-015, отдельная задача).
- Кастомная иконка приложения — сейчас стандартная иконка шаблона Tauri, в `mvp-done.md` не требуется.
- Автообновление, CI/GitHub Actions (T-108, релиз 1.1).

## Риски и вопросы

- Repowise `get_risk` по `tauri.conf.json`, `Cargo.toml`, `README.md`, `docs/mvp-done.md`,
  `docs/guide.md`, `docs/backlog.md`: hotspot score 0% у всех, 0 зависимых файлов, единственный автор —
  пользователь. Риска для стабильности кода нет, это конфиг и документация.
- Смена `productName` при уже существующем `target/` может оставить старые артефакты со старым именем —
  закрыто шагом 2 (пересборка с нуля при необходимости).
- Proxy-проверка на одном Mac не ловит то, что реально ловит второй Mac (другая версия macOS,
  отсутствие Xcode CLT у получателя) — риск принят пользователем явно в интервью.
