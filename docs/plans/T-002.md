## Проблема

После T-001 есть каркас, но нет линтера, форматтера и тестового раннера: работают только скрипты
`dev`, `build`, `preview`, `typecheck`, `tauri`. Следующие задачи (`src/domain/`, Rust, UI) пишутся по TDD
и опираются на `pnpm test` и `pnpm lint`; их же требует пункт 25 в `docs/mvp-done.md`.

## Решения из интервью

- Q1–Q2 ESLint: flat config, typescript-eslint `recommended` без типовой информации, плюс `react-hooks` и
  `react-refresh` (типы проверяет `pnpm typecheck`). Prettier — отдельно, `eslint-config-prettier` гасит конфликты.
- Q3–Q5 Окружение `jsdom`, конфиг Vitest блоком `test` в `vite.config.ts`, без `globals: true` (явный
  `import { describe, it, expect } from "vitest"`); единственный тест — RTL smoke-тест рендера `App`.
- Q6–Q7 Конфиг Prettier ключом `"prettier"` в `package.json` (лимит 6 файлов). `pnpm lint` падает на предупреждениях
  (`--max-warnings 0`), охват — весь репозиторий, в ignores `dist/`, `node_modules/`, `src-tauri/`, `coverage/`.
- Q8–Q9 Покрытие, git-хуки, CI, линт Markdown — вне рамок, строками в `docs/later.md`. Пункт 25
  в `docs/mvp-done.md` отмечается в этой задаче после реального прогона команд.

## Решение

Четыре инструмента в штатных конфигурациях, закреплённые скриптами `package.json`: `lint`, `format`,
`format:check`, `test` (плюс существующий `typecheck`). ESLint получает flat config `eslint.config.js`;
Prettier настраивается ключом в `package.json` и по умолчанию уважает `.gitignore`, поэтому
`.prettierignore` не нужен. Vitest живёт в общем `vite.config.ts`: один конфиг, общие плагины, нет риска
расхождения. Связку Vitest + jsdom + RTL + jest-dom доказывает smoke-тест, который рендерит `App`. Почему так:
конфиги минимальные и стандартные, линтер не дублирует `tsc` и остаётся быстрым. Отклонено:
`eslint-plugin-prettier` — замедляет линт и мешает ошибки формата с логическими.

## Критерии приёмки

- [ ] На чистом дереве проходят `pnpm lint` (код 0, без предупреждений), `pnpm format:check`, `pnpm typecheck`;
      `pnpm test` делает один прогон (не watch): 1 тест, 0 падений.
- [ ] Линтер ловит ошибку: строка `const unused = 1;` в `src/App.tsx` → `pnpm lint` падает; удалить строку → проходит.
- [ ] Форматтер ловит ошибку: испорченный отступ в `src/App.tsx` → `pnpm format:check` падает, `pnpm format` чинит
      → проходит; правку откатить.
- [ ] В `src-tauri/` проходят `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`.
- [ ] **Commands** в `AGENTS.md` перечисляет все пять frontend-скриптов, и каждая команда реально запускается;
      пункт 25 в `docs/mvp-done.md` отмечен `[x]` после фактического прогона трёх команд.

## Файлы

- `package.json` — изменить — devDependencies, скрипты `lint`/`format`/`format:check`/`test`, ключ `"prettier"`.
- `eslint.config.js` — создать — typescript-eslint recommended, react-hooks, react-refresh, prettier, ignores.
- `vite.config.ts` — изменить — блок `test` (jsdom, setupFiles) + `/// <reference types="vitest/config" />`.
- `src/test/setup.ts` — создать — `import "@testing-library/jest-dom/vitest";`.
- `src/App.test.tsx` — создать — smoke-тест рендера `App`.
- `AGENTS.md` — изменить — реальный раздел **Commands**.
- Процессные файлы (`docs/backlog.md`, `mvp-done.md`, `later.md`, `handoff.md`) в лимит не входят.

## Шаги

1. Установить devDependencies: `eslint`, `@eslint/js`, `typescript-eslint`, `eslint-plugin-react-hooks`, `eslint-plugin-react-refresh`,
   `globals`, `prettier`, `eslint-config-prettier`, `vitest`, `jsdom`, `@testing-library/{react,dom,jest-dom}`.
2. Написать `eslint.config.js`, прогнать `pnpm lint`, точечно починить найденное в коде T-001.
3. Добавить ключ `"prettier"` (`printWidth: 100`, остальное — умолчания), прогнать `pnpm format`.
4. Добавить блок `test` в `vite.config.ts`, создать `src/test/setup.ts` и `src/App.test.tsx`.
5. Прогнать `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, `pnpm test` — все зелёные.
6. Обновить **Commands** в `AGENTS.md`, отметить пункт 25 в `mvp-done.md`, «Вне рамок» — в `later.md`.

## Вне рамок

Покрытие (`@vitest/coverage-v8`), git-хуки, CI, линт Markdown в `docs/`, e2e (запрещён ADR 0007), типовой
линтинг (`recommendedTypeChecked`), правила стиля сверх recommended, тесты бизнес-логики (домен — T-004).

## Риски и вопросы

- ESLint `recommended` может найти нарушения в коде T-001 (например, `@ts-expect-error` в
  `vite.config.ts`). Чиним точечно на шаге 2, без рефакторинга и с комментарием.
- При `include: ["src"]` тест и setup попадают под `tsc --noEmit`. Если типы jest-dom не подхватятся,
  подключаем их импортом `@testing-library/jest-dom/vitest` в setup, а не правкой `tsconfig.json`.
- Предложение: дописать выбранные конфиги строкой в Consequences ADR 0007. Сам ADR не правлю.
