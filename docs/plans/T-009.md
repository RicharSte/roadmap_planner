# T-009: UI — node CRUD, перенос к другому родителю, смена статуса

Статус: approved

## Проблема

После T-008 дерево и панель деталей — только просмотр. Нельзя создать/переименовать/удалить ноду,
перенести её к другому родителю или сменить статус — нельзя закрыть соответствующие пункты `mvp-done.md`.

## Решения из интервью

- Создание: инлайн-`<input>` в тулбаре сайдбара (Enter — сохранить, Escape — отмена), не `prompt()`.
- Две кнопки: «+ Корень» (всегда активна) и «+ Дочерняя» (активна при выбранной ноде).
- Переименование: кнопка в DetailsPanel → заголовок превращается в инлайн-`<input>`; Enter/blur — сохранить,
  Escape — отмена.
- Удаление: кнопка в DetailsPanel, немедленно, без confirm (confirm — явно T-013).
- Перенос и перестановка — через drag&drop нативным HTML5 Drag and Drop API (без новых зависимостей,
  согласовано явно вместо `@dnd-kit`/`react-dnd`). 3 зоны на строке дерева: верхняя/нижняя треть —
  вставить как sibling до/после (линия-индикатор), средняя треть — сделать ребёнком (подсветка строки).
  Перестановка внутри одного родителя — в рамках T-009 (явное решение пользователя, расход рамок строки
  бэклога зафиксирован).
- Невалидные цели (сам узел, его потомки) — курсор `not-allowed`, drop не применяется; `DomainError CYCLE` —
  запасной барьер, не основной путь.
- Клавиатурный fallback для переноса/перестановки — вне рамок, в `later.md`.
- Статус: нативный `<select>` в DetailsPanel на `STATUS_ORDER`/`STATUS_LABELS`.
- Ошибки сохранения — отдельное поле `saveError` в `useProject` (не путать с `error` открытия/создания),
  общий баннер без финальной полировки текста (T-013).
- Без оптимистичного обновления: состояние меняется только после успешного `saveProject`.
- Авто-выбор: после создания — выбирается новая нода; после удаления выбранной (или её ветки) —
  `selectedId` сбрасывается в `null`; при переносе выбор не меняется.

## Решение

`useProject` получает `update(compute: (p: Project) => Project)`: считает `compute(project)`, ловит
`DomainError` → `saveError`; иначе `saveProject(newProject)` → при ошибке `saveError`, при успехе —
`setProject`, плюс обобщённое правило выбора (новый id в `nodes` → выбрать его; старый `selectedId`
исчез из `nodes` → `null`; иначе не трогать). `deleteNode` возвращает `{project, deletedIds}` —
`deletedIds` пока не используется (файлов описаний ещё не существует до T-010).
`TreeSidebar` сам знает `parentId` каждой строки через рекурсию рендера (без доп. пропа `parentIndex`);
drag-зоны считает по `getBoundingClientRect` строки; список недопустимых целей — локальный обход
`getChildren`. Перенос и вставка-sibling — один и тот же вызов `moveNode`, с поправкой индекса на сдвиг
после удаления внутри одного родителя (`moveNode` сам удаляет узел из старого места перед вставкой).
Отклонено: контрол-`<select>` для переноса — заменён на drag&drop по решению пользователя.

## Шаги

1. `useProject.update()` + `saveError` + правило выбора.
2. `DetailsPanel`: переименование, удаление, `<select>` статуса.
3. `TreeSidebar`: кнопки создания + инлайн-инпут.
4. `TreeSidebar`: drag&drop (zones, cycle-guard, индикаторы), проводка в `App.tsx`.
5. `App.css`, тесты, прогон проверок.

## Тесты

Create (root/child) → новая нода, выбрана; EMPTY_TITLE/TITLE_TOO_LONG → `saveError`. Rename, status select,
delete (выбранной и не выбранной). Move: drag через `fireEvent.dragStart/dragOver/drop` с ручным
`dataTransfer`-стабом и замоканным `getBoundingClientRect` на 3 зоны; cycle — drop на потомка не меняет
дерево. `saveProject` замокан на ошибку → `saveError`, дерево не меняется.

## Вне рамок

Confirm удаления (T-013), финальные/i18n тексты ошибок (T-013), клавиатурный fallback переноса (`later.md`),
очистка `descriptions/<id>.md` удалённых нод (неактуально до T-010).

## Риски и вопросы

6 файлов — на пределе лимита из-за объединения CRUD + drag&drop в одной задаче (решение пользователя).
`moveNode` требует индекс после удаления узла из старого места — при перестановке внутри одного родителя
индекс сдвигается; код должен это учитывать (не доменная, а UI-логика). 3-зонная модель drag&drop
зафиксирована в ADR 0012.
