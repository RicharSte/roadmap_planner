# T-007: Создание нового проекта (пустая папка → roadmap.json + descriptions/)

Статус: approved

## Проблема

Сейчас можно только открыть папку с уже существующим `roadmap.json` (T-005). Если пользователь
выбирает пустую папку, `open_project` просто возвращает ошибку `EMPTY_FOLDER` — создать проект
в ней нельзя. ADR 0009 уже описывает механизм (`create_project` пишет только в `pending` вида
`Empty`), но команды и TS-адаптера для этого ещё нет.

## Решения из интервью

Интервью не нужно: открытых вопросов нет, все решения покрыты ADR 0005 (схема пустого проекта),
ADR 0009 (механизм `create_project` через существующий `pending`, без нового диалога) и ADR 0011
(атомарная запись, порядок файлов). Новые коды ошибок — рядовая реализация в стиле уже
существующих (`EMPTY_FOLDER`, `PENDING_NOT_PROJECT`), не решение, требующее выбора пользователя.

## Решение

`create_project(content)` в Rust переиспользует `pending` вида `Empty`, который уже выставляет
`open_project` при пустой папке (диалог выбора папки не открываем второй раз — ADR 0009).
Перед записью папка перепроверяется на пустоту (гонка: файлы могли появиться после выбора).
При успехе создаётся `descriptions/`, атомарно пишется `roadmap.json`, затем `pending` становится
`root` — без отдельного вызова `commit`, он для другого случая (открытие существующего проекта).
На TS-стороне `createEmptyProject()` в домене даёт `{ version: 1, rootIds: [], nodes: {} }`;
`createProject()` в сторадже проводит его через `parseProject`/`validateProject` (как и `saveProject`),
сериализует и вызывает Rust-команду. UI-кнопки нет — появится в T-008/T-009, пункт
`docs/mvp-done.md` про создание проекта останется неотмеченным.

## Критерии приёмки

- [ ] `cargo test` зелёный: новые тесты `create_project` (успех, нет `pending`, `pending` вида
      `Roadmap`, папка перестала быть пустой, невалидный JSON — файл не создаётся)
- [ ] `cargo clippy --all-targets -- -D warnings` чистый

- [ ] `pnpm lint` чистый (`--max-warnings 0`)
- [ ] Ручная проверка откладывается до UI (T-008/T-009); пункт `mvp-done.md` не отмечается

## Шаги

1. В `project.rs` вынести проверку «есть видимые файлы» из `read_roadmap` в `fn has_visible_files`.
2. Добавить `ProjectState::create(&mut self, content: &str) -> Result<(), AppError>`:
   `pending` отсутствует → `NO_PENDING_PROJECT`; вид `Roadmap` → `PENDING_NOT_EMPTY`;
   `has_visible_files` → `FOLDER_NOT_EMPTY`; JSON невалиден → `INVALID_JSON` (ничего не пишем);
   иначе создать `descriptions/`, `write_inside(.., "roadmap.json", ..)`, `pending.take()` → `root`.
3. Команда `#[tauri::command] pub fn create_project(state, content: String)`; зарегистрировать в `lib.rs`.
4. В `tree.ts` добавить `createEmptyProject()`.
5. В `projectStorage.ts` добавить `"PENDING_NOT_EMPTY" | "FOLDER_NOT_EMPTY"` в `StorageErrorCode`
   и функцию `createProject(): Promise<OpenResult>` (строит пустой проект, валидирует, `invoke`,
   при успехе — `{ kind: "opened", project }`, при ошибке — `fromRustError`).
6. Тесты Rust и TS, затем прогнать все команды из критериев приёмки.

## Тесты

- `ProjectState::create`: успех (root выставлен, файл и `descriptions/` на диске); без `pending`;
  `pending` вида `Roadmap`; папка стала не пустой между выбором и созданием; невалидный JSON
  (ничего не записано)
- `createEmptyProject()`: результат проходит `parseProject(JSON.parse(JSON.stringify(...)))`
  и `validateProject()`
- `createProject()`: успешный путь вызывает `invoke("create_project", { content })` и возвращает
  `opened`; ошибки Rust (`PENDING_NOT_EMPTY`, `FOLDER_NOT_EMPTY`, `INVALID_JSON`) маппятся в `error`

## Вне рамок

UI-кнопка «Создать проект», подтверждение в интерфейсе (T-008/T-009). Миграция схемы,
отличная от v1. Диалог выбора папки для создания — переиспользуем `pending` от `open_project`.
