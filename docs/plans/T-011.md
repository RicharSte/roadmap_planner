# T-011: Автосохранение описания (debounce), индикатор несохранённого, предупреждение при закрытии

Статус: approved

## Проблема

Редактор описания (`DescriptionEditor.tsx`, T-010b) сохраняет текст только при потере фокуса (blur) или
при размонтировании (смена ноды). Если пользователь печатает и закрывает окно приложения, не выходя
из поля редактора, правка нигде не фиксируется и теряется без предупреждения. Пункт `mvp-done.md`
«Закрыть и снова открыть приложение → все изменения сохранены (автосохранение)» не закрыт.
ADR 0006 требует debounce для автосохранения описания — сейчас его нет.

## Решения из интервью

- Закрытие окна: `getCurrentWindow().onCloseRequested(...)` (без нового permission — просто listener).
  Если есть несохранённое — `event.preventDefault()` + нативный `window.confirm(...)`; при подтверждении —
  `getCurrentWindow().destroy()`. Для `destroy()` нужен новый permission `core:window:allow-destroy`
  в `src-tauri/capabilities/default.json` (ограничен окном `"main"`, уже так в файле). Плагин `dialog`
  не используется — не тащим второй permission.
- Debounce: 800 мс после последней клавиши.
- «Несохранённое» = `draft !== saved` в открытом редакторе описания **ИЛИ** `saveError !== null`
  (последняя попытка сохранить не удалась) — обе ситуации считаются и для индикатора, и для предупреждения.
- Индикатор: текст «Не сохранено» рядом с переключателем «Редактор/Просмотр», **только когда** не сохранено;
  исчезает, когда `draft === saved` и `saveError === null`. Без промежуточных статусов «Сохранение…»/«Сохранено».

## Решение

`DescriptionEditor.tsx`: единая функция `flush()` (через существующие `draftRef`/`savedRef`/`pathRef`) —
вызывает `onSave`, при успехе обновляет `saved`. `handleBlur` и debounce-таймер вызывают `flush()`;
логика unmount-сохранения не меняется. В `onChange` CodeMirror: `setDraft` + сброс/перезапуск
`setTimeout(flush, 800)` через `useRef<number>`; таймер чистится при unmount. Новые пропсы:
`onDirtyChange(dirty: boolean)` — эффект на `[draft, saved]` вызывает его с `draft !== saved`, в cleanup —
`onDirtyChange(false)`; `hasSaveError: boolean` — прокидывается для индикатора. Индикатор рендерится рядом
с `description-mode-switch`, когда `draft !== saved || hasSaveError`.

`DetailsPanel.tsx`: новые пропсы `onDescriptionDirtyChange`, `hasSaveError` — прокидываются в
`DescriptionEditor` как `onDirtyChange`/`hasSaveError`.

`App.tsx`: `const [descriptionDirty, setDescriptionDirty] = useState(false)`; передаёт
`onDescriptionDirtyChange={setDescriptionDirty}` и `hasSaveError={saveError !== null}` в `DetailsPanel`.
`hasUnsavedRef` (через `useEffect`) держит актуальное `descriptionDirty || saveError !== null`.
Один `useEffect` при монтировании регистрирует `getCurrentWindow().onCloseRequested`: если
`hasUnsavedRef.current` — `preventDefault()` + `window.confirm(...)`; подтверждено → `destroy()`; иначе
ничего. `unlisten()` в cleanup.

`src-tauri/capabilities/default.json`: добавить `"core:window:allow-destroy"` в `permissions`.

Почему так: `flush()` переиспользует существующие refs вместо новой стейт-машины — минимум кода.
`window.confirm()` вместо плагина `dialog` — один permission вместо двух и без новой зависимости.
Отклонено: debounce через библиотеку (`lodash.debounce`) — для одного `setTimeout` не нужна зависимость.

## Тесты

`App.test.tsx`: debounce — правка без blur, `vi.advanceTimersByTime(800)` → `writeDescription` вызван один
раз с финальным текстом; быстрая серия правок перезапускает таймер, лишних вызовов нет. Индикатор —
появляется при правке, исчезает после успешного сохранения; остаётся видимым при ошибке записи вместе с
`save-error-banner`. Закрытие окна — мок `onCloseRequested` вызывается с объектом `{ preventDefault }`;
без несохранённого — `preventDefault` не вызван; с несохранённым — вызван, затем мок `window.confirm`
(`vi.spyOn(window, "confirm")`) определяет, вызван ли `destroy`.

## Вне рамок

Retry записи при занятом файле на Windows и предупреждение именно по этой причине — `docs/later.md`
(`[T-011]`, существующая строка). Перезагрузка с диска — T-012. Склонения и финальные тексты ошибок —
T-013. Debounce для структурных изменений дерева (rename/move/status) — не нужен, они уже сохраняются
сразу при каждом действии (`useProject.update`), не посимвольно. Промежуточный статус «Сохранение…» —
не делаем, индикатор двухпозиционный.

## Риски и вопросы

- Repowise: `useProject.ts` — hotspot 88% (большой/сложный `useProject`, critical), `App.test.tsx` —
  hotspot 96% (churn), `App.tsx` — 48%, `DetailsPanel.tsx` — 64%, `DescriptionEditor.tsx` — 44% (все растущие).
  Все пятеро обычно меняются вместе (co-change confirmed для `useProject.ts`/`App.tsx`/`App.test.tsx`/
  `DetailsPanel.tsx`) — все в плане, фикс вносится минимально, без рефакторинга `useProject`/`App`.
- Новый permission `core:window:allow-destroy` — согласован в интервью (Q1), ограничен окном `"main"`.
- На macOS `Cmd+Q` может обходить `onCloseRequested` окна (если это общий app-exit, а не закрытие окна) —
  в приложении нет меню/трея, которые вызывали бы `exit()` напрямую, поэтому ожидается тот же путь через
  закрытие единственного окна; проверить вручную в рамках ручных критериев. Если `Cmd+Q` обходит —
  стоп и эскалация (отдельный Rust-side `RunEvent::ExitRequested` — новый объём работы, не в этом плане).
- Паттерн «подтверждение перед закрытием окна = нативный `confirm()` + `core:window:allow-destroy`»
  закреплён в ADR 0014 (accepted) — T-012 и будущие окна/диалоги переиспользуют его, не добавляют второй.
