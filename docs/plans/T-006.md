# T-006: Rust — атомарная запись JSON и `.md` + тесты

Статус: approved

## Проблема

Проект можно открыть (T-005), но не сохранить: без записи нет автосохранения (T-011), создания проекта (T-007) и описаний (T-010).
Запись обязана быть атомарной (ADR 0002): сбой или отключение питания не должны оставить полузаписанный `roadmap.json` или `.md`.

## Решения из интервью (правила записи — ADR 0011)

- Q1 В задаче: `write_inside`, команды `save_roadmap(content)` и `write_description(path, content)`, TS-адаптер с тестами.
- Q18 `write_inside(root, rel, bytes)` сама вызывает `resolve_inside`. Q2 Только `std`, порядок записи — ADR 0011 п. 2–4.
- Q3 `save_roadmap` проверяет синтаксис JSON (`serde_json::Value`) → иначе `INVALID_JSON`, файл не тронут; схему — только домен.
- Q4 `write_description` принимает только `descriptions/<name>.md`, `<name>` = `[A-Za-z0-9_-]+`, иначе `INVALID_PATH`.
  Q5 Нет папки `descriptions/` → создаётся (`create_dir`, один уровень).
- Q6 Конфликты с внешними правками не проверяем, последняя запись побеждает. Q8 Лимит 10 МБ (`FILE_TOO_LARGE`) для обоих файлов.
- Q7 `saveProject` пишет `JSON.stringify(project, null, 2) + "\n"`. Q9 Сначала `validateProject`; проблемы → `INVALID_PROJECT`
  - `problems`, `invoke` не вызывается. Оба TS-метода возвращают `SaveResult = { kind: "saved" } | { kind: "error", code, message, problems? }`.
- Q10 Windows: цель занята другой программой → сразу `IO_ERROR`, temp удалён, без повторов в Rust; повтор — следующее автосохранение.
- Q11 Права копируются на temp; read-only → `READ_ONLY`. Q12 Symlink внутрь проекта → пишем в настоящий файл, ссылка сохраняется.
- Q13 Потеря hard links, xattr/тегов Finder, ACL, владельца при `rename` — принимаем для MVP.
- Q14/Q17 Оставшиеся `.tmp` **не применяются** (могут быть неполными или старее цели). `commit_project` после установки `root`
  удаляет `.roadmap.json.tmp` и `descriptions/.<name>.md.tmp` строго по шаблону; ошибки удаления игнорируются.
- Q15 Пока файл занят (Q10), правки живут только в памяти; закрытие приложения в этот момент их теряет. Не T-006.
- Без интервью: команды синхронные, держат `Mutex<ProjectState>` всю запись (ADR 0011 п. 5); нет проекта → `NO_PROJECT_OPEN`.

## Решение

`atomic.rs`: `write_inside(root, rel, bytes)` — `resolve_inside` → размер → symlink в реальный путь (Q12) → read-only (Q11) → запись (Q2);
`remove_stale_temps(root)` — уборка (Q17). `ProjectState::save_roadmap`/`write_description`: Q3/Q4 → Q5 → `write_inside`;
`commit` после успеха вызывает `remove_stale_temps`. Команды Tauri только склеивают методы с состоянием. TS: `saveProject`, `writeDescription`.
Отклонено: `tempfile` в runtime (новая зависимость), применение `.tmp` при открытии (Q14).

## Тесты

- `write_inside`: новый файл создан; существующий перезаписан; `.<имя>.tmp` после успеха нет; `../x` → `INVALID_PATH`; 10 МБ + 1 →
  `FILE_TOO_LARGE`; read-only → `READ_ONLY`, не изменён; старый temp удалён; цель — папка → `IO_ERROR`, temp не остался. `#[cfg(unix)]`:
  права `600` сохранены; temp-имя — symlink наружу → внешний файл цел; цель — symlink внутрь → ссылка осталась, реальный файл обновлён.
- `remove_stale_temps`: удаляет `.roadmap.json.tmp` и `descriptions/.n_a.md.tmp`; не трогает `.DS_Store`, `notes.tmp`, `descriptions/n_a.md`;
  нет `descriptions/` → без ошибки. `commit` при `Roadmap` вызывает уборку, при ошибке commit — нет.
- `ProjectState`: обе записи без `root` → `NO_PROJECT_OPEN`; `save_roadmap("{")` → `INVALID_JSON`, файл не изменён; валидный → записан.
  `write_description`: `roadmap.json`, `descriptions/a.txt`, `descriptions/sub/a.md`, `descriptions/../a.md`, `descriptions/a b.md`,
  `descriptions/.md` → `INVALID_PATH`; нет `descriptions/` → создана, файл записан; пустое содержимое → записано.
- Адаптер: `saveProject` валидный → `invoke("save_roadmap", { content })` с отступом 2 и `\n` → `saved`; невалидный → `INVALID_PROJECT`,
  `invoke` не вызван; ошибка Rust → тот же `code`. `writeDescription` → `invoke("write_description", { path, content })` → `saved`; ошибка → `code`.

## Вне рамок

Создание проекта (T-007), чтение `.md` и редактор (T-010), debounce и показ ошибок (T-011), защита от перезаписи после битой
перезагрузки (T-012), русские тексты (T-013), конфликты, retry, xattr, предупреждение при закрытии, удаление `.md` при удалении узла.

## Риски и вопросы

- Уборка удаляет файлы пользователя с именем ровно `.roadmap.json.tmp` / `descriptions/.<id>.md.tmp` — шаблон узкий, принимаем (ADR 0011 п. 10).
- Группа файлов не атомарна: T-010 обязан писать `.md` раньше `roadmap.json` (ADR 0011 п. 8). В T-006 только одиночные записи.
