# T-010: DnD fix + Rust/storage: чтение и удаление файлов описаний

Статус: approved

## Проблема

Перенос нод мышью из T-009 не работает в собранном приложении: строку можно взять, индикатор зоны
показывается, но после отпускания дерево не меняется. Для редактора описаний (T-010b) нет способа
прочитать `descriptions/<id>.md` (есть только запись) и удалить файлы описаний удалённой ветки.
Без этого не закрыть пункты `mvp-done.md`: «Перенести ноду к другому родителю», «Создать описание…»,
«Удалить ноду с подтверждением…».

## Решения из интервью

- Разбивка: T-010 (эта часть: DnD + Rust/storage) и T-010b (UI: редактор, предпросмотр, подтверждение
  удаления) — превышение лимита 10 файлов. Строку T-010b в backlog добавляет агент с разрешения пользователя.
- DnD, симптом: drag начинается, индикатор зоны есть, `drop` не срабатывает. Фикс 1: `"dragDropEnabled": false`
  в окне `tauri.conf.json` (Tauri перехватывает drag-события webview для нативного drop файлов).
  Если фикс 1 не помог — фикс 2: `draggable` и drag-обработчики на кнопке-заголовке строки.
- Чтение описания: лимит 10 МБ, как у `roadmap.json`. Нет файла — это не ошибка (UI покажет пустой
  редактор, файл создастся при сохранении). Не UTF-8 — ошибка `NOT_UTF8`.
- Удаление нод удаляет `.md` всей ветки. Навсегда (`fs::remove_file`), без корзины и нового crate.
  Порядок (реализует T-010b): сначала сохранить `roadmap.json`, потом удалить файлы. Отсутствующий файл — не ошибка.

## Решение

1. `tauri.conf.json`: в окно добавить `"dragDropEnabled": false`. Нативный drop файлов из Finder нам не нужен.
2. Rust, `ProjectState::read_description(path) -> Result<Option<String>, AppError>`:
   `NO_PROJECT_OPEN` → `validate_description_path` → `resolve_inside` (symlink наружу → `PATH_OUTSIDE_PROJECT`)
   → нет файла → `Ok(None)`; папка → `IO_ERROR`; > 10 МБ → `FILE_TOO_LARGE`; не UTF-8 → `NOT_UTF8`.
3. Rust, `ProjectState::delete_descriptions(paths: &[String]) -> Result<(), AppError>`: сначала проверяет
   **все** пути (`validate_description_path`), при любой ошибке ничего не удаляет; затем для каждого
   `resolve_inside` + `remove_file`; `NotFound` пропускается; папка или другая ошибка → `IO_ERROR`.
4. Команды Tauri `read_description` и `delete_descriptions`, регистрация в `lib.rs`. Это свои команды
   приложения — capabilities не меняются.
5. `projectStorage.ts`: `readDescription(path)` → `{kind:"loaded", content} | {kind:"missing"} | {kind:"error",…}`;
   `deleteDescriptions(paths)` → `SaveResult`, пустой список — без `invoke`.

Почему так: Rust остаётся единственным местом доступа к файлам и проверки путей (ADR 0009); пакетное
удаление — один IPC-вызов и одна ошибка. Отклонено: `ask`/корзина — новые capability или crate.

## Тесты

Rust `read_description`: без проекта → `NO_PROJECT_OPEN`; невалидный путь (`../a.md`, `descriptions/a.txt`)
→ `INVALID_PATH`; нет файла → `None`; есть файл → содержимое; пустой файл → `Some("")`; > 10 МБ →
`FILE_TOO_LARGE`; не UTF-8 → `NOT_UTF8`; symlink наружу (unix) → `PATH_OUTSIDE_PROJECT`.
Rust `delete_descriptions`: без проекта → ошибка; файлы удаляются; отсутствующий пропускается; один
невалидный путь в списке → ошибка и ни один файл не удалён; пустой список → `Ok`.
TS: `readDescription` — loaded / missing (`null` из Rust) / ошибка Rust → `{kind:"error", code}`;
`deleteDescriptions` — передаёт `paths`, пустой список не вызывает `invoke`, ошибка Rust → `error`.
