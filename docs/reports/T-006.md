# Отчёт T-006: Атомарная запись `roadmap.json` и `.md` + тесты

## Что сделано

Добавлена единая точка атомарной записи файлов проекта в Rust и адаптеры для фронтенда.
Теперь `saveProject` и `writeDescription` пишут через временный файл `.<имя>.tmp` в той же папке,
а затем делают `rename`: сбой или отключение питания не оставляют полузаписанный файл.
Запись защищена от выхода за пределы папки проекта, read-only файлов, слишком больших данных
и symlink-атак.

## Как это работает

### `src-tauri/src/atomic.rs`

- **`write_inside(root, rel, bytes)`** — единая функция записи.
  - Проверяет размер (лимит 10 МБ).
  - Вызывает `resolve_inside`, чтобы убедиться, что путь не выходит за `root`.
  - Если цель — symlink внутрь проекта, следует по нему и пишет в реальный файл; сама ссылка остаётся.
  - Если существующий файл read-only — сразу возвращает `READ_ONLY`, не создавая temp.
  - Удаляет устаревший `.<имя>.tmp` (в том числе битый symlink).
  - Создаёт temp через `create_new`, пишет байты, копирует права с цели, делает `sync_all`.
  - Атомарно переименовывает temp в цель; при ошибке temp удаляется.
  - На Unix делает `fsync` родительской папки.
- **`remove_stale_temps(root)`** — удаляет `root/.*.tmp` и `root/descriptions/.*.tmp`.
  Ошибки игнорируются; `.DS_Store`, `notes.tmp` и обычные `.md` не трогаются.
- **`is_read_only(path)`** — определяет read-only файл на Unix (mode) и Windows (атрибут).
- **`resolve_symlink(root, candidate)`** — для symlink внутрь проекта возвращает реальный путь.
- **`sync_dir(path)`** — синхронизирует каталог через `File::open(...).sync_all()`.

### `src-tauri/src/project.rs`

- **`ProjectState::validate_description_path(path)`** — проверяет, что путь строго `descriptions/<name>.md`,
  где `<name>` состоит из `[A-Za-z0-9_-]`.
- **`ProjectState::save_roadmap(content)`** — без открытого проекта возвращает `NO_PROJECT_OPEN`;
  проверяет JSON через `serde_json::Value` (`INVALID_JSON` без записи);
  вызывает `write_inside(root, "roadmap.json", ...)`; при успехе чистит `.tmp`.
- **`ProjectState::write_description(path, content)`** — проверяет путь, при необходимости создаёт
  `descriptions/`, записывает через `write_inside`, чистит `.tmp`.
- **`ProjectState::commit`** — для `Roadmap` теперь вызывает `remove_stale_temps` после установки `root`.
- **`save_roadmap`** и **`write_description`** — Tauri-команды, склеивающие `Mutex<ProjectState>` с методами.

### `src/storage/projectStorage.ts`

- **`saveProject(project)`** — сначала `validateProject`; при ошибке возвращает `INVALID_PROJECT` без вызова Rust.
  При успехе сериализует `JSON.stringify(project, null, 2) + "\n"` и вызывает `save_roadmap`.
- **`writeDescription(path, content)`** — вызывает `write_description`.
- Оба метода возвращают `SaveResult`: `{ kind: "saved" }` или `{ kind: "error", code, message, problems? }`.

## Как проверить руками

1. Запустить `pnpm tauri dev`.
2. В DevTools выполнить:
   ```js
   const s = await import("/src/storage/projectStorage.ts");
   const r = await s.openProject();
   ```
   Выбрать папку с примером из ADR 0005.
   Ожидаемо: `r.kind === "opened"`.
3. Выполнить `await s.saveProject(r.project)`.
   Ожидаемо: `{ kind: "saved" }`, в папке проекта `roadmap.json` с отступом 2, файла `.roadmap.json.tmp` нет.
4. Удалить папку `descriptions/`, затем выполнить `await s.writeDescription("descriptions/n_b.md", "# hi")`.
   Ожидаемо: папка `descriptions/` и файл `n_b.md` созданы, `{ kind: "saved" }`.
5. В терминале выполнить `chmod 444 roadmap.json`, снова `await s.saveProject(r.project)`.
   Ожидаемо: `{ kind: "error", code: "READ_ONLY" }`, содержимое `roadmap.json` не изменилось.
6. Создать файл `.roadmap.json.tmp` в папке проекта, затем открыть проект заново.
   Ожидаемо: после открытия `.roadmap.json.tmp` удалён.
