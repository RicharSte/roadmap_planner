# Отчёт T-005: открытие папки проекта и чтение `roadmap.json`

## Что сделано

Появилась первая реальная связь между диском и доменом: пользователь может выбрать папку через системный диалог, Rust возвращает сырой текст `roadmap.json`, а фронтенд парсит его через уже готовый `parseProject` и подтверждает открытие. Также добавлен безопасный helper `resolve_inside`, который не выпускает пути за пределы папки проекта — он понадобится в T-006 и T-010.

## Как это работает

### `src-tauri/src/paths.rs`

- **`AppError`** — универсальный тип ошибки с полями `code` и `message`. Сериализуется в JSON и отправляется во фронтенд. Сообщения на английском (русские тексты — T-013).
- **`AppError::new` / `AppError::io`** — конструкторы ошибок.
- **`validate_relative_path`** — проверяет строку пути: не пустая, не абсолютная, без `.`/`..`, без `\` и `:`.
- **`resolve_inside(root, rel)`** — строит путь `root/rel`, находит ближайшего существующего предка, канонизирует его и проверяет, что он остаётся внутри `root`. Это ловит symlink наружу. Разрешает пути к ещё не созданным файлам (например, будущему `descriptions/<id>.md`).

### `src-tauri/src/project.rs`

- **`PendingView` / `PendingProject`** — кандидат на открытие: папка + вид (Roadmap/Empty).
- **`ProjectState::new`** — пустое состояние.
- **`ProjectState::set_pending`** — запоминает выбранную папку. Новый кандидат заменяет старый, уже открытый `root` не трогается.
- **`ProjectState::commit`** — делает кандидата текущим открытым проектом. Ошибка, если кандидата нет или он пустой.
- **`ProjectState::root`** — возвращает папку текущего проекта.
- **`ProjectState::reload`** — перечитывает `roadmap.json` из текущего проекта.
- **`read_roadmap(dir)`** — читает `roadmap.json` из папки: проверяет, что это папка; игнорирует скрытые файлы при определении пустоты; проверяет существование и размер файла (не более 10 МБ); читает как UTF-8. Код `EMPTY_FOLDER` — не окончательный отказ: папка сохраняется как `PendingView::Empty` и может стать основой для создания проекта в T-007.
- **`open_project`** (async команда) — показывает системный диалог выбора папки, канонизирует путь, запоминает кандидата, читает `roadmap.json`. При отмене возвращает `null`.
- **`commit_project`** — команда для подтверждения кандидата после успешного `parseProject`.
- **`reload_project`** — команда для перезагрузки уже открытого проекта.

### `src/storage/projectStorage.ts`

- **`openProject`** — вызывает `open_project` в Rust. Если `null` → `cancelled`. Иначе `JSON.parse` → `parseProject` → `commit_project`. При ошибках возвращает `INVALID_JSON`, `INVALID_PROJECT` или код из Rust.
- **`reloadProject`** — вызывает `reload_project`, парсит, но **никогда** не вызывает `commit_project`.
- **`fromRustError`** — превращает объект ошибки Rust в `{ code, message }`.

## Как проверить руками

1. Создать тестовую папку, положить в неё `roadmap.json` по примеру из ADR 0005 (2 узла).
2. Запустить `pnpm tauri dev`.
3. Открыть DevTools (`Cmd+Option+I`).
4. В консоли выполнить:
   ```js
   const { openProject } = await import("/src/storage/projectStorage.ts");
   console.log(await openProject());
   ```
   - Выбрать тестовую папку → ожидаемо `{ kind: "opened", project: { ... } }`.
   - Нажать «Отмена» → ожидаемо `{ kind: "cancelled" }`.
   - Выбрать пустую папку → ожидаемо `{ kind: "error", code: "EMPTY_FOLDER" }`.
   - Выбрать папку с битым `roadmap.json` (`{`) → ожидаемо `{ kind: "error", code: "INVALID_JSON" }`.
5. Для перезагрузки:
   ```js
   const { reloadProject } = await import("/src/storage/projectStorage.ts");
   console.log(await reloadProject());
   ```
   - Ожидаемо тот же проект; если `roadmap.json` стал битым — ошибка, но файл не перезаписывается.

Интерактивная часть в этой сессии не выполнялась автоматически, так как требует выбора папки в системном диалоге. Dev-сборка запускается без ошибок.
