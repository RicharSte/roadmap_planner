# Отчёт T-004: `src/domain/` — типы, индекс родителей, операции над узлами, валидация

## Что сделано

Реализован чистый TypeScript-домен для проектов дорожной карты. Появились типы данных, парсинг и проверка `roadmap.json`, операции над деревом (создание, переименование, удаление поддерева, перемещение, смена статуса и описания) и генератор безопасных id. Все операции не мутируют входные данные: возвращают новый объект `Project`, а неизменённые узлы остаются теми же ссылками.

## Как это работает

### `src/domain/types.ts`

- `Project` — корневой объект: `version`, `rootIds` и словарь `nodes`.
- `RoadmapNode` — узел с `id`, `title`, `childrenIds`, `status`, `descriptionPath`, `createdAt`, `updatedAt`.
- `NodeStatus` — четыре допустимых статуса.
- `ParentIndex` — `Map<string, string[]>`, связывает узел с массивом его родителей.
- `DomainError` — ошибка с машинным `code` и сообщением на английском.

### `src/domain/ids.ts`

- `createNodeId(nodes)` — генерирует `n_` + 10 символов из алфавита `0-9a-z` без `i`, `l`, `o`, `u`. Проверяет коллизию со словарём `nodes`, при необходимости повторяет до 20 попыток.

### `src/domain/validate.ts`

- `parseProject(raw)` — разбирает нетипизированный JSON. Проверяет, что вход — объект, поле `version === 1`, `rootIds` — массив строк, `nodes` — объект. Для каждого узла проверяет наличие и тип всех полей, отбрасывает лишние. Возвращает либо `{ ok: true, project }`, либо `{ ok: false, problems }`.
- `validateProject(project)` — проверяет целостность типизированного проекта: все ссылки на id разрешимы, у узла не больше одного родителя, нет сирот, нет циклов, нет дубликатов в `rootIds`/`childrenIds`, `descriptionPath` равен `descriptions/<id>.md` или `null`.

### `src/domain/tree.ts`

- `buildParentIndex(project)` — обходит дерево и строит `ParentIndex`.
- `getParents(index, id)` — возвращает родителей узла по готовому индексу.
- `getChildren(project, id)` — возвращает `childrenIds` узла.
- `createNode(project, title, parentId?, index?, now?)` — создаёт узел, вставляет в корень или к родителю. Нормализует заголовок (переводы строк → пробел, trim), проверяет длину 1–120 символов.
- `renameNode(project, id, title, now?)` — меняет заголовок с той же валидацией.
- `deleteNode(project, id)` — удаляет узел и всё поддерево. Возвращает `{ project, deletedIds }`.
- `moveNode(project, id, newParentId, index?)` — перемещает узел к другому родителю, в корень или внутри одного родителя. Запрещает перенос в себя или в потомка.
- `setStatus(project, id, status, now?)` — меняет статус на один из четырёх допустимых.
- `setDescriptionPath(project, id, path, now?)` — устанавливает путь описания; повторная установка того же пути обновляет `updatedAt`, смена на другой путь запрещена.

## Как проверить руками

1. Открыть проект и запустить `pnpm test`.
   Ожидаемо: 51 тест пройден, 3 файла с тестами.
2. Запустить `pnpm typecheck`, `pnpm lint`, `pnpm format:check`.
   Ожидаемо: все три команды завершаются без ошибок.
3. Убедиться, что `grep -rn "@tauri-apps\|invoke(" src/domain/` ничего не находит.
   Ожидаемо: пустой вывод.
