# Отчёт T-010: DnD fix + Rust/storage: чтение и удаление файлов описаний

## Что сделано

В окно приложения добавлен флаг `dragDropEnabled: false`, чтобы Tauri не перехватывал HTML5 drag-and-drop события. В Rust-части появились команды для чтения и пакетного удаления файлов `descriptions/<id>.md` с проверкой путей и лимитом 10 МБ. В адаптере хранилища добавлены асинхронные обёртки для этих команд.

## Как это работает

### `ProjectState::read_description(path)`

- Проверяет, что проект открыт (`NO_PROJECT_OPEN`), и что путь имеет вид `descriptions/<name>.md` (`INVALID_PATH`).
- Через `resolve_inside` убеждается, что путь не выходит за пределы проекта (`PATH_OUTSIDE_PROJECT`), включая symlink наружу.
- Если файла нет — возвращает `Ok(None)`; UI покажет пустой редактор.
- Если по пути папка — `IO_ERROR`.
- Если размер больше 10 МБ — `FILE_TOO_LARGE`.
- Читает содержимое; при `InvalidData` возвращает `NOT_UTF8`.

### `ProjectState::delete_descriptions(paths)`

- Проверяет открытый проект.
- Пустой список — немедленный `Ok`.
- Сначала валидирует **все** пути и проверяет их через `resolve_inside`; при любой ошибке ни один файл не удаляется.
- Затем для каждого пути вызывает `fs::remove_file`.
- `NotFound` пропускается; папка или другая ошибка → `IO_ERROR`.

### Команды Tauri

- `read_description(state, path) -> Result<Option<String>, AppError>`
- `delete_descriptions(state, paths: Vec<String>) -> Result<(), AppError>`

Оба являются собственными командами приложения; capabilities не изменялись.

### `projectStorage.ts`

- `readDescription(path)` возвращает `{ kind: "loaded", content }`, `{ kind: "missing" }` или `{ kind: "error", code, message }`.
- `deleteDescriptions(paths)` возвращает `SaveResult`; при пустом списке `invoke` не вызывается.

## Как проверить руками

1. `pnpm tauri dev`. Создать или открыть проект с несколькими нодами.
2. Перетащить ноду на середину другой строки.
   Ожидаемо: перетаскиваемая нода стала дочерней цели.
3. Перетащить ноду на верхнюю или нижнюю треть строки.
   Ожидаемо: нода встала сиблингом до или после цели, порядок сохранился.
4. Перетащить ноду на себя или на своего потомка.
   Ожидаемо: курсор `not-allowed`, дерево не меняется.
5. Перезапустить приложение и открыть ту же папку.
   Ожидаемо: структура дерева и порядок нод сохранились.
6. (Через T-010b) Открыть редактор описания для ноды, у которой ещё нет `.md`.
   Ожидаемо: редактор пустой, сохранение создаёт `descriptions/<id>.md`.
7. (Через T-010b) Удалить ветку с файлами описаний.
   Ожидаемо: после сохранения `roadmap.json` все `.md` ветки удалены из папки.

## Отклонения от плана

- Ручная проверка drag-and-drop в `pnpm tauri dev` не выполнялась автоматически, потому что требует физического взаимодействия с окном. Логика DnD покрыта существующими тестами в `App.test.tsx`; фикс 1 (`dragDropEnabled: false`) применён. Если он не поможет, потребуется фикс 2 из плана.
- `pnpm format` отформатировал несколько файлов вне плана (`.mcp.json`, `.vscode/extensions.json`, `docs/reports/T-009.md`), чтобы `pnpm format:check` проходил чисто.
