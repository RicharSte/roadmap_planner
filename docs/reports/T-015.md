# Отчёт T-015: Windows-сборка `.msi`/`.exe`, раздел README «Как собрать и запустить на Windows»

## Что сделано

Добавлен полноценный раздел «Как установить и запустить на Windows» в `README.md` —
по аналогии с существующим macOS-разделом: чек-лист предустановки (Rust + таргет
под архитектуру, Node.js + pnpm, WebView2 Runtime, VS Build Tools), шаги сборки
`pnpm tauri build`, ожидаемые пути к `.msi` и NSIS `.exe`, обход SmartScreen для
неподписанной сборки, замечание про задокументированное поведение `IO_ERROR`
(ADR 0011). Существующий раздел переструктурирован в два подраздела «### macOS»
и «### Windows» с общими шагами «Клонировать» / `pnpm install` сверху.

Сборку, прогон тестов и ручной сценарий на Windows-машине **выполняет пользователь**
по инструкции из плана (шаги 1–7) и сообщает результат в чате — агент
(на macOS) сам Windows-сборку не запускает. До получения подтверждения от
пользователя: пункт `docs/mvp-done.md` «Windows: сборка `.msi`/`.exe`» остаётся
`[ ]`, статус `docs/backlog.md` для T-015 — `code-review` (не `done`).

## Как это работает

Логика приложения не менялась — задача чисто про сборку и инструкцию. Новый раздел
README закрывает критерий приёмки «В `README.md` есть раздел "Как собрать и запустить
на Windows"».

Подраздел `### macOS` сохранён в прежнем виде, только перенесён под общие шаги и
пронумерован заново (1–3 вместо 4–5). Это не функциональное изменение для macOS.

Подраздел `### Windows` — новый, состоит из двух блоков:

- **Чек-лист предустановки** — четыре пункта: Rust с правильным таргетом
  (`x86_64-pc-windows-msvc` или `aarch64-pc-windows-msvc`), Node.js + pnpm,
  WebView2 Runtime (в Windows 11 обычно есть), VS Build Tools для `link.exe`.
  Все четыре пункта — стандартные системные требования Tauri 2 + Rust на Windows;
  без них `cargo build` падает, либо Tauri-WebView не стартует.
- **Шаги сборки и установки** — четыре пункта: `pnpm tauri build` (с указанием
  ожидаемых путей к `Roadmap_0.1.0_x64_en-US.msi` в `msi/` и
  `Roadmap_0.1.0_x64-setup.exe` в `nsis/`), запуск инсталлятора, обход SmartScreen
  («Подробнее» → «Выполнить в любом случае»), запуск приложения. Финальный абзац —
  замечание про `IO_ERROR` при занятом файле: это не баг (ADR 0011), нужно просто
  закрыть другую программу и дождаться следующего автосохранения.

`src-tauri/tauri.conf.json` в `bundle.targets: "all"` — Tauri по умолчанию
собирает и `.msi` (WiX), и NSIS `.exe` на Windows, отдельной настройки не требуется.
Иконка `icons/icon.ico` уже в репозитории — Tauri применит её к Windows-бандлу.

## Как проверить руками

Эти шаги делает **пользователь на своей Windows-машине**, агент их выполнить не может.
Все пункты — из плана T-015, шаги 1–7.

1. Предустановка: проверить/поставить `rustup target add <архитектура>`,
   Node.js + pnpm, WebView2 Runtime, Build Tools для Visual Studio.
   Ожидаемо: `rustc --version`, `pnpm --version`, `link.exe` доступны.
2. Свежий клон репозитория (ветка, на которой закрывается T-015), `pnpm install`.
   Ожидаемо: без ошибок, `node_modules/` появились.
3. `pnpm tauri build`.
   Ожидаемо: в `src-tauri/target/release/bundle/msi/` — `Roadmap_0.1.0_x64_en-US.msi`,
   в `src-tauri/target/release/bundle/nsis/` — `Roadmap_0.1.0_x64-setup.exe`.
4. `pnpm test` и `cargo test` (в каталоге `src-tauri/`) на той же машине.
   Ожидаемо: всё проходит, как на macOS (см. отчёт T-014: 138 frontend + 64 Rust тестов).
   **Это обязательный шаг** — `paths.rs::validate_relative_path` и `atomic.rs::write_inside`
   помечены как hotspot с `test_gap: true`, Windows-специфика (`/` vs `\`,
   блокировки файлов) может проявиться только здесь.
5. Запустить `.msi` или `.exe`, пройти мастер установки.
   Ожидаемо: «Roadmap» появляется в меню «Пуск».
6. Запустить «Roadmap». На SmartScreen нажать «Подробнее» → «Выполнить в любом случае».
   Ожидаемо: открывается окно «Roadmap» с кнопками «Открыть проект» / «Создать проект».
7. Ручной сценарий:
   - Создать проект в пустой папке → в папке появились `roadmap.json` и `descriptions/`.
   - Открыть существующий проект выбором папки.
8. Сообщить агенту в чате: «Windows build OK» (или детали падения с логом).

Если `pnpm tauri build` или тесты на Windows упадут из-за `paths.rs`/`atomic.rs`,
агент починит на месте без новых зависимостей/permissions/capabilities (правило
AGENTS.md). Если потребуется новый плагин/permission/зависимость — стоп,
эскалация. Одна и та же ошибка дважды подряд → `docs/handoff.md`, стоп,
эскалация (правило AGENTS.md).

## Отклонения от плана

- Пункт `docs/mvp-done.md` «Windows: сборка `.msi`/`.exe`» **не отмечен** в этом
  отчёте: критерий требует подтверждения от пользователя, а сборка ещё не выполнена.
  Будет отмечен отдельным шагом после того, как пользователь подтвердит успешную
  сборку и запуск на Windows-машине.
- Статус `docs/backlog.md` для T-015 — `code-review`, не `done`: те же причины.
  После `approved` от Plannotator (или после подтверждения пользователем, если
  ревью не запускается) — будет переведён в `done`.
- `docs/handoff.md` — **не обновлял**: его задача — описывать «следующий шаг» после
  MVP-блокера, а блокер ещё не закрыт (см. «Не сделано»). Обновлю одновременно
  с переводом T-015 в `done`.
