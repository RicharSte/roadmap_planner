собрано в релизный `.app` и `.dmg`. Проверена proxy-установка на этом же Mac (монтирование

`docs/mvp-done.md` отмечен по фактически подтверждённым пунктам, пункт про «другой Mac»

## Как это работает

Логика приложения не менялась: правки коснулись только отображаемого имени, метаданных бандла
и документации. Tauri при сборке подставляет `productName` и `identifier` в `Info.plist`
бандла и использует их в имени `.app`/`.dmg`. Поле `identifier` (`dev.roadmap.app`)
оставлено без изменений — это bundle-ID для Gatekeeper и будущей нотаризации, по решению
из интервью трогать только видимые пользователю строки.

`Cargo.toml` `name` (`tauri-app`) и `tauri_app_lib` оставлены как есть — это внутренние
идентификаторы, не видимые пользователю; их переименование не входит в MVP (см. «Вне рамок»
в плане). Внутри `.app` бинарник по-прежнему называется `tauri-app`, но `Info.plist`
и `.app`-бандл видны как `Roadmap` — то есть пользователь увидит «Roadmap», а не
«tauri-app».

## Как проверить руками

Полный сценарий выполняется в собранном `.app`, **не** в `pnpm tauri dev`. Ниже — пункты
из `docs/mvp-done.md`, которые должен пройти пользователь в `/Applications/Roadmap.app`.

Подготовительные шаги (агент уже выполнил их в этой сессии — для повторной проверки):

1. В корне проекта: `pnpm tauri build`.
   Ожидаемо: в консоли — `Bundling Roadmap.app` и `Bundling Roadmap_0.1.0_aarch64.dmg`,
   без ошибок.
2. В Finder: открыть `src-tauri/target/release/bundle/dmg/Roadmap_0.1.0_aarch64.dmg`.
   Ожидаемо: смонтируется том `Roadmap`, в нём — `Roadmap.app` и alias `Applications`.
3. Если в `/Applications` уже есть `Roadmap.app` от прошлой сборки — удалить её
   (Finder → «Переместить в корзину»). Перетащить свежий `Roadmap.app` в `/Applications`.
   Ожидаемо: `.app` лежит в `/Applications/Roadmap.app`, `Info.plist` содержит
   `CFBundleDisplayName=Roadmap` и `CFBundleIdentifier=dev.roadmap.app`.
4. Отмонтировать том (Finder → ⏏ рядом с иконкой `Roadmap`).
5. Запуск: Finder → `/Applications` → ПКМ на `Roadmap.app` → «Открыть» → в диалоге
   Gatekeeper — «Открыть» (для неподписанной сборки это нужно один раз).
   Ожидаемо: открывается окно «Roadmap» с сайдбаром проекта и кнопками «Открыть»/«Создать».
6. Дальше — по чек-листу:

   - Создать новый проект: «Создать проект» → выбрать пустую папку → появились `roadmap.json`
     и `descriptions/`.
   - Открыть существующий проект выбором папки.
   - Добавить корневую ноду и дочернюю ноду.
   - Переименовать ноду, сменить статус (4 фиксированных: открыт/в работе/заблокировано/завершено).
   - Перенести ноду к другому родителю (drag-and-drop в сайдбаре).
   - Удалить ноду с подтверждением; удаление ветки предупреждает о дочерних нодах.
   - Создать описание ноды, отредактировать Markdown, увидеть предпросмотр справа.
   - Закрыть и снова открыть приложение → все изменения сохранены.
   - Изменить `.md` во внешнем редакторе → кнопка «Перезагрузить» подхватывает правки.
   - Повредить `roadmap.json` снаружи (любой невалидный JSON) → понятное сообщение,
     файл не перезаписан.

Каждый пункт `[x]` агент проставит в `docs/mvp-done.md` только после подтверждения.

## Отклонения от плана

- Пункт mvp-done про «другой Mac» заменён на proxy-проверку по решению из интервью
  (второго Mac нет). Формулировка явно это отражает.
- Бинарник внутри `.app/Contents/MacOS` оставлен под именем `tauri-app`. Это сознательное
  решение — переименование Cargo-пакета не входит в MVP и было явно вынесено в «Вне рамок»
  плана. На пользовательский опыт не влияет: в Finder и в Dock видно «Roadmap».

## Не сделано / риски

- Подпись и нотаризация macOS — пользователь увидит предупреждение Gatekeeper при первом
  запуске (`ПКМ → Открыть`). Это поведение по плану, не дефект. Запланировано в
  `docs/later.md` (T-301).
- `pnpm tauri dev` сценарии пользователя не повторялись на собранном `.app` — пункты
  чек-листа, которые подтверждаются только в собранном приложении (`Сценарии пользователя`),
  остаются `[ ]` до ручного прогона пользователем.
- Windows-сборка (T-015) намеренно не делается в этой задаче.
