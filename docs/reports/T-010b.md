# Отчёт T-010b: редактор описания, предпросмотр и подтверждение удаления

## Что сделано

В панели деталей теперь можно создать описание ноды, отредактировать его в Markdown-редакторе, переключаться между редактором и предпросмотром, а при удалении ветки увидеть, сколько нод и файлов описаний будет удалено. Удаление больше не происходит сразу — нужно подтвердить действие.

## Как это работает

### `useProject.ts`

- `update` — теперь возвращает `true`, если `roadmap.json` успешно сохранён, и `false` при любой ошибке. Это нужно, чтобы удаление файлов описаний шло только после успешного изменения дерева.
- `createDescription(id)` — формирует путь `descriptions/<id>.md`, сначала пустой файл через `writeDescription`, а только потом обновляет `roadmap.json` через `setDescriptionPath`. Если файл не записался — `roadmap.json` не меняется.
- `loadDescription(path)` — проксирует вызов `readDescription`.
- `saveDescription(path, content)` — пишет файл через `writeDescription`. При ошибке показывает баннер и возвращает `false`.
- `deleteNode(id)` — до изменения дерева через `deleteNode` из `src/domain/tree.ts` собирает `descriptionPath` всех удаляемых нод. После успешного сохранения `roadmap.json` вызывает `deleteDescriptions`. Если удаление файлов не удалось — дерево уже обновлено, но пользователь видит баннер об ошибке.

### `DescriptionEditor.tsx`

- При монтировании (а благодаря `key={node.id}` он монтируется заново при смене ноды) загружает файл через `onLoad`.
- Три состояния: `loading`, `ready`, `missing`, `error`.
- Если текст непустой — открывается «Просмотр», если пустой или файла нет — «Редактор».
- Редактор — `CodeMirror` с расширениями `markdown()` и `EditorView.lineWrapping`, без номеров строк и folding.
- Сохранение происходит при потере фокуса редактора и при размонтировании компонента (переключение на другую ноду). Если текст не менялся — запроса к диску нет.
- При ошибке чтения (`NOT_UTF8`, `FILE_TOO_LARGE`) редактор доступен только для чтения.
- Предпросмотр через `ReactMarkdown` + `remarkGfm`. Ссылки рендерятся как `<span>`, картинки — как `<span>{alt}</span>`, сырой HTML не интерпретируется.

### `DetailsPanel.tsx`

- Если `descriptionPath === null` — кнопка «Создать описание».
- Если путь есть — встраивается `DescriptionEditor`.
- При нажатии «Удалить» появляется блок подтверждения с текстом: «Удалить «<title>»? Будет удалено нод: N (из них дочерних: K), файлов описаний: M.» Числа считаются чистой доменной функцией `deleteNode(project, id).deletedIds`, без сохранения.
- Подтверждение скрывается автоматически, если пользователь выбрал другую ноду.

### `App.tsx`

- Из `useProject` забирает `createDescription`, `loadDescription`, `saveDescription` и передаёт их в `DetailsPanel`.

## Как проверить руками

1. `pnpm tauri dev`. Выбрать папку с проектом или создать новый.
2. Выбрать ноду без описания. Нажать «Создать описание». В папке `descriptions/` должен появиться пустой `<id>.md`, в панели — «Редактор».
3. Ввести текст, кликнуть другую ноду. Открыть `<id>.md` вне приложения — там должен быть введённый текст. Вернуться к ноде — должен открыться «Просмотр» с текстом.
4. В описании написать:
   ```markdown
   # Заголовок

   - пункт 1
   - пункт 2

   | колонка 1 | колонка 2 |
   | --------- | --------- |
   | 1         | 2         |

   [ссылка](https://example.com)
   ```
   В «Просмотре» должны отобразиться заголовок, список, таблица и текст ссылки без активной ссылки.
5. Удалить файл `.md` снаружи, выбрать ноду в приложении — должен появиться пустой редактор с пометкой «Файл не найден, будет создан при сохранении».
6. Выбрать ветку с описаниями, нажать «Удалить». В блоке подтверждения должны быть верные числа нод, дочерних нод и файлов описаний. «Отмена» — ничего не меняет. «Удалить» — ноды исчезают, их `.md` удалены с диска.
7. Перезапустить приложение и открыть ту же папку — дерево и описания на месте.

## Ответы на замечания ревью

1. **`.mcp.json`, строка 5** — конфигурационный файл MCP-сервера `repowise` (уже был в репозитории). Изменение — только автоматическое форматирование Prettier (`pnpm format`), не функциональное.
2. **`docs/reports/T-010b.md`, строка 67** — это пример Markdown из ручного теста, написанный внутри блока кода. В самом приложении ссылки в предпросмотре намеренно рендерятся как некликабельный текст (требование плана и ADR 0006: «ссылки — текст без перехода»). Компонент `DescriptionEditor.tsx` заменяет `components.a` на `<span>`, поэтому поведение соответствует заданию.
3. **Замечание о кликабельных ссылках** — текущее поведение некликабельных ссылок является намеренным ограничением MVP. Идея сделать ссылки кликабельными в будущем добавлена в `docs/later.md`.
